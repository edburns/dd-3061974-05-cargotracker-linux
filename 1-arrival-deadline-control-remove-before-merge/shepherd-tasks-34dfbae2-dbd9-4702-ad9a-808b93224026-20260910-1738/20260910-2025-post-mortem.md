## Section 8: Observations and Recommendations

### 8.1 What Worked Well

- **Serial dependency control:** every task began only after the preceding PR merged, preserving the planned application-to-UI dependency chain.
- **Layered validation:** focused unit tests, Maven/Open Liberty builds, CI, local browser validation, local review, CCRA, and exact-head merge gates caught different defect classes.
- **Fast convergence:** all tasks merged, three on the first CCRA round and two after one correction round.
- **Strong merge safety:** every merge verified the non-`main` base, current reviewed head, successful checks, mergeability, and zero unresolved threads.
- **Control integrity:** lesson propagation remained off and the campaign lessons file stayed unchanged.

### 8.2 What Could Improve

- Stage 30 did not detect the three JSF lifecycle defects later raised on [#10](https://github.com/edburns/dd-3061974-05-cargotracker-linux/pull/10). The focused test suite should explicitly cover null `FacesContext`, Cancel with invalid required input, and Update validation failure.
- CCRA overview-only advisories are not represented by inline comment counts. Treating only review comments and unresolved threads as actionable can undercount review concerns.
- The campaign-level clock includes 55 minutes not attributable to exported CLI sessions. Explicit orchestration start/end markers around each stage would make queue and handoff latency measurable.
- Token telemetry is only partially useful because token types and the span-level input/output values are redacted.

### 8.3 Recommendations

1. Extend the stage-40 parser to inspect structured CCRA overview sections such as `Previously missed findings`, not only inline review comments. If advisory text is present with `Findings: None`, record the discrepancy and require an explicit disposition before merge.
2. Add reusable JSF dialog regression checks for no-context launcher/close behavior, immediate Cancel semantics, and `args.validationFailed`-guarded Update completion.
3. Emit a compact per-stage result artifact containing issue, PR, start/end timestamps, review ID, review head, round count, inline count, overview advisory count, CI result, correction commits, and merge commit. This would remove most post-mortem text mining.
4. Record orchestration gaps explicitly as assignment wait, CCA wait, inter-stage handoff, CCRA wait, and CI wait so control/treatment comparisons can distinguish agent work from platform latency.
5. Preserve the current exact-head, non-`main`, passing-CI, zero-unresolved-thread merge gates; they prevented stale review evidence from being accepted.
