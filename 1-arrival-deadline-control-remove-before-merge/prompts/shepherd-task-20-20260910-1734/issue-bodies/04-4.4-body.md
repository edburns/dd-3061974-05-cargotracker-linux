## Implement

Create:

- `src/main/java/org/eclipse/cargotracker/interfaces/booking/web/ChangeArrivalDeadlineDateDialog.java`
- `src/main/webapp/admin/dialogs/changeArrivalDeadlineDate.xhtml`

The launcher must be serializable and use:

```java
@ManagedBean(name = "changeArrivalDeadlineDateDialog")
@SessionScoped
```

Implement `showDialog(String trackingId)`, `handleReturn(SelectEvent event)`, and `cancel()`. `showDialog` must pass the single tracking ID as `Map<String, List<String>>`, configure the exact resolved options, and open the resolved path. `cancel()` closes with an empty string and does not invoke the facade. Preserve the existing destination-dialog return-handling behavior.

The XHTML title is `Change Deadline`. Place this before `h:head`:

```xhtml
<f:metadata>
    <f:viewParam name="trackingId"
                 value="#{changeArrivalDeadlineDate.trackingId}"/>
    <f:viewAction action="#{changeArrivalDeadlineDate.load}"/>
</f:metadata>
```

Display read-only `Origin:` from `changeArrivalDeadlineDate.cargo.originName` and `Destination:` from `changeArrivalDeadlineDate.cargo.finalDestinationName`. Provide an associated `Deadline:` label, validation feedback, and a required `p:datePicker` bound to `changeArrivalDeadlineDate.arrivalDeadlineDate`. Add Cancel invoking `changeArrivalDeadlineDateDialog.cancel()` and Update invoking `changeArrivalDeadlineDate.changeArrivalDeadline()`.

Run the application and directly request:

`http://localhost:8080/cargo-tracker/admin/dialogs/changeArrivalDeadlineDate.xhtml?trackingId=DEF789`

Verify HTTP 200, title, context values, selected existing deadline, Cancel preserving the value, Update changing it, and no `TagException`, `Parent UIComponent`, `FacesException`, or server error. Verify destination editing still works.
