The resolved design is concrete: load the cargo, replace its `RouteSpecification` with one containing the existing origin, existing destination, and supplied `Date`, apply it through `Cargo.specifyNewRoute(...)`, and store the aggregate. Preserve the assigned itinerary and let the aggregate recalculate delivery and routing state; in the established sequential test the cargo remains `MISROUTED`. Require a non-null deadline but add no new chronological rule. Research established that the historical Arquillian suite remains tied to remote Payara and is compiled but skipped by the prepared Open Liberty build; do not modernize that runtime or add a mocking dependency.

## Implement

Modify only:

- `src/main/java/org/eclipse/cargotracker/application/BookingService.java`
- `src/main/java/org/eclipse/cargotracker/application/internal/DefaultBookingService.java`
- `src/test/java/org/eclipse/cargotracker/application/BookingServiceTest.java`

Add this application API:

```java
void changeDeadline(TrackingId trackingId, Date deadline);
```

Implement it by:

1. Calling `cargoRepository.find(trackingId)`.
2. Reading the current destination from `cargo.getRouteSpecification().getDestination()`.
3. Creating a replacement `RouteSpecification` from `cargo.getOrigin()`, that current destination, and `deadline`.
4. Calling `cargo.specifyNewRoute(routeSpecification)`.
5. Calling `cargoRepository.store(cargo)`.
6. Logging the tracking ID and new deadline at `Level.INFO` in the style of `changeDestination(...)`.

Write the test first. Append sequential `testChangeDeadline()` after `testChangeDestination()`. Advance the original test deadline by one month, invoke the new operation, reload through `Cargo.findByTrackingId`, and assert:

- origin is still Chicago and destination is still Helsinki;
- the stored deadline is the same calendar day as requested;
- the assigned itinerary is unchanged;
- transport status is `NOT_RECEIVED`;
- last known location is `Location.UNKNOWN`;
- current voyage is `Voyage.NONE`;
- the cargo is not misdirected;
- ETA is `Delivery.ETA_UNKOWN`;
- next expected activity is `Delivery.NO_ACTIVITY`;
- it is not unloaded at destination;
- routing status remains `MISROUTED`.

Use the repository's existing Java EE 7, Java 7 source-level, JUnit, Arquillian, logging, and date-comparison patterns.
